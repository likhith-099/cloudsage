01 Executive Overview & Problem Statement

1.1 The Cloud Complexity Challenge

Modern enterprise cloud environments deployed on Amazon Web Services (AWS) consist of thousands of disparate resources: compute instances across multiple availability zones, scalable object storage buckets, distributed CloudWatch monitoring alarms, and multi-tier billing dimensions. Cloud administrators, DevOps engineers, and FinOps analysts face significant operational friction:

  • Console Overload: Navigating dozens of AWS Management Console screens to correlate an EC2 instance's status with its CloudWatch CPU telemetry and historical cost driver is slow and error-prone.
  • CLI Overhead: Running complex, one-off AWS CLI commands with cumbersome JMESPath filters requires deep syntax recall and introduces context-switching.
  • Knowledge Fragmentation: Answering architectural and troubleshooting questions (e.g., "Why is my burstable T3 instance pegged at 100% CPU?" or "How do S3 lifecycle transitions work?") requires separate searches through external AWS documentation.
  • Currency Mismatch for Indian Teams: Standard AWS billing is denominated strictly in USD, forcing Indian cloud engineers and financial decision-makers to manually convert exchange rates and re-format numbers into lakhs and crores.

1.2 The CloudSage Solution

CloudSage is an intelligent, local, GenAI-powered cloud operations and FinOps assistant. Operating directly on the engineer's workstation or internal enterprise server, CloudSage bridges the gap between natural language questions and concrete AWS infrastructure telemetry:

🤖 Natural Language Cloud Operations

Inspect EC2 instances, list S3 buckets, analyze CloudWatch CPU utilization, and break down cloud spend using conversational prompts.

📚 Grounded RAG Knowledge Base

Instantly answers AWS conceptual, architectural, and troubleshooting questions with verified source citations from official documentation.

💰 Native INR (₹) FinOps Intelligence

All cost analyses and service breakdowns are presented in Indian Rupees using proper Indian number formatting (e.g., ₹40,995.50).

🛡️ Strict Read-Only Security Model

CloudSage is architected with zero write or destructive capabilities, operates under least-privilege IAM policies, and binds strictly to local loopback.

3.2 LLM Provider Abstraction & Seamless Fallback

The LLMClient in app/ai/llm.py provides a vendor-neutral interface supporting three execution backends:

  1. OpenAI (gpt-4o-mini): Utilizes OpenAI's native function-calling API. Tool definitions are passed via JSON schema. If tool calls are requested, the agent executes them and feeds results back into OpenAI for synthesis.
  2. Google Gemini (gemini-1.5-flash / gemini-2.0-flash): Leverages Google's tool-declaration API for automated function dispatch.
  3. Local Deterministic Intent Engine: A built-in, regex- and keyword-driven classification engine that provides immediate, zero-latency tool selection and synthesis offline without third-party API keys.
Zero-Failure Fallback Guarantee: If an OpenAI or Gemini API call fails due to invalid API keys, rate limits, or network timeouts, LLMClient catches the exception and automatically falls back to the Local Deterministic Engine, ensuring uninterrupted operation.

4.3 Deterministic Local Semantic Embeddings Engine

To eliminate heavy PyTorch/TensorFlow dependencies, GPU requirements, or paid embedding API calls, CloudSage implements LocalSemanticEmbeddings in app/rag/embeddings.py:

  • Subword N-Gram Hashing: Tokenizes text and extracts word tokens (weight = 1.5) and character 3-grams (weight = 0.5) to capture semantic prefixes and suffixes.
  • Dual-Bucket MD5 Projection: Hashes each feature using MD5 into two distinct 384-dimensional projection indices with alternating signs to minimize hash collisions.
  • L2 Normalization: Normalizes the resulting 384-dimensional dense vector to unit length ($\|v\|_2 = 1.0$), ensuring that the dot product directly equals the cosine similarity.
  • Performance: Generates embeddings in less than 0.5 milliseconds per chunk with zero network overhead.

4.4 Vector Store & Cosine Similarity Ranking

The VectorStore (app/rag/vector_store.py) manages indexed vectors in memory and serializes them to ./data/vector_store/index.json. The similarity between query vector $Q$ and document vector $D$ is calculated as:

$$ ext{Cosine Similarity}(Q, D) = rac{\sum_{i=1}^{n} Q_i \cdot D_i}{\sqrt{\sum_{i=1}^{n} Q_i^2} \cdot \sqrt{\sum_{i=1}^{n} D_i^2}}$$

Results above a minimum score threshold (default 0.05) are sorted in descending order, and the top-K chunks are passed to the synthesizer with metadata (source title, category, and URL).

05 AWS Integrations, Telemetry & Boto3 Wrappers

5.1 AWS Session & Credential Resolution

The app/services/aws_session.py module manages AWS authentication using the standard Boto3 credential resolution chain:

  1. Explicit parameters passed in .env (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN).
  2. Environment variables set in the host OS shell.
  3. Shared AWS credential and config files (~/.aws/credentials and ~/.aws/config).
  4. AWS Single Sign-On (AWS SSO) token cache.
  5. IAM Roles attached to EC2 instances or ECS/EKS task execution roles.

5.2 Boto3 Operational Client Wrappers

All operational tools strictly wrap read-only AWS APIs and handle error masking and pagination gracefully:

1. EC2 Instance Inventory (app/tools/ec2.py)

Invokes ec2.describe_instances() to discover all virtual machines in the configured region. It iterates over Reservations and Instances, extracting instance IDs, types, running states (running, stopped, pending), availability zones, private IPs, public IPs, launch times, and the Name tag from the tags list.

2. S3 Bucket Inventory (app/tools/s3.py)

Invokes s3.list_buckets() to enumerate all buckets in the account along with their creation timestamps. Safety Guarantee: The tool never calls GetObject, ListObjectsV2, or any data-plane API, ensuring zero access to sensitive object contents.

3. CloudWatch Telemetry Extractor (app/tools/cloudwatch.py)

Invokes cloudwatch.get_metric_statistics() for the AWS/EC2 namespace with the metric CPUUtilization. It queries over a configurable time window (default 1 hour, up to 168 hours) with a 300-second period, aggregating Average, Maximum, and Minimum statistics. It sorts datapoints chronologically and computes the overall average and peak spike percentage.

4. AWS Cost Explorer Spend Aggregator (app/tools/cost_explorer.py)

Invokes ce.get_cost_and_usage() with Granularity='MONTHLY' and metric UnblendedCost, grouped by DIMENSION: SERVICE. It sums unblended costs across all active services, calculates percentage contributions, identifies the top cost driver, and passes the result to the currency engine for INR localization.

06 Currency Localization Engine & FinOps Intelligence

6.1 Motivation for Native INR (₹) Formatting

For cloud engineering and FinOps teams in India, analyzing cloud bills in raw USD introduces cognitive friction. Standard International number formatting (grouping every 3 digits, e.g., 100,000,000) differs significantly from the Indian numbering system (grouping in Hundreds, Thousands, Lakhs, and Crores, e.g., 10,00,00,000). CloudSage provides a dedicated currency engine (app/services/currency.py) to standardize all financial telemetry.

6.2 The Indian Number Formatting Algorithm

The format_inr function implements the formal Indian digit grouping algorithm:

Indian Number System Grouping Rules
Input Amount: 14250000.75
  1. Separate Integer ('14250000') and Decimal ('75') parts.
  2. Extract last 3 digits: '000' (Hundreds).
  3. Group remaining digits ('14250') in pairs of 2 from right to left: ['1', '42', '50'].
  4. Combine with commas: "1,42,50,000"
  5. Append currency symbol and decimal: "₹1,42,50,000.75" (One Crore Forty-Two Lakh Fifty Thousand)

6.4 FinOps Intelligence & Rightsizing Directives

When users inquire about cloud spending, the agent incorporates 6 core FinOps optimization strategies into its response:

  • Compute Rightsizing: Identifies instances with average CPU below 10% and recommends downsizing (e.g., migrating from t3.large to t3.small saves ~50%).
  • Idle Resource Scheduling: Automated shut-off for non-production development environments outside business hours saves ~65% on EC2 compute.
  • Commitment Discounts: Recommends 1-year or 3-year Savings Plans and Reserved Instances for steady-state workloads (up to 72% discount).
  • S3 Storage Lifecycle Optimization: Transitioning data from S3 Standard to S3 Intelligent-Tiering or Glacier saves between 50% and 95% on storage costs.
  • Unattached Resource Cleanup: Detecting unattached EBS volumes, obsolete EBS snapshots, and idle Elastic IPs.

8.2 Security Invariants & System Guardrails

🔒 100% Read-Only Assurance

CloudSage contains no code paths calling RunInstances, TerminateInstances, DeleteBucket, or PutObject. Accidental infrastructure damage is impossible.

🛡️ Zero Secret Leakage

AWS secret access keys and session tokens are never returned by API routes, never logged to stdout, and never rendered in frontend HTML.

🌐 Local Loopback Binding

Default deployment binds strictly to 127.0.0.1:8000, preventing unauthorized network access from external interfaces.

🛑 Untrusted Context Isolation

Retrieved RAG documentation chunks are treated as untrusted text. System instructions cannot be overridden by document contents.

8.3 The 10 System Prompt Directives

  1. No Hallucination: Never invent or hallucinate AWS infrastructure data.
  2. Tool Discipline: Always invoke operational tools when live cloud resource details are requested.
  3. Document Grounding: Ground architectural and troubleshooting concepts in retrieved AWS documentation.
  4. Source Transparency: Clearly distinguish between Live AWS data, Mock development data, and Knowledge Base guidance.
  5. Mandatory Citations: Cite official AWS documentation titles and URLs for knowledge inquiries.
  6. INR Standardization: Display all cloud spending in Indian Rupees (₹) with proper Indian digit grouping. Never mix $ and ₹.
  7. Professional Tone: Structure technical answers using clean Markdown tables, bullet points, and bold headers.
  8. Credential Protection: Never request or output AWS secret keys.
  9. Read-Only Invariant: Refuse and reject any user requests attempting destructive operations.
  10. Graceful Error Handling: If an API call fails, explain the exact root cause (e.g., missing IAM permission) rather than guessing.

10.2 Step-by-Step Local Setup Guide

  1. Clone & Navigate to Repository: 
    cd cloudsage-main
  2. Create & Activate Python Virtual Environment: 
    python -m venv .venv
# On Windows (PowerShell):
.venv\Scripts\Activate.ps1
# On Linux/macOS (Bash):
source .venv/bin/activate
  3. Install Dependencies: 
    pip install -r requirements.txt
  4. Build/Ingest the RAG Knowledge Base: 
    python -m app.rag.ingest
  5. Run the Test Suite: 
    pytest tests/ -v
  6. Launch the Local Development Server: 
    uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

    • Web Dashboard: http://127.0.0.1:8000/

11.2 Extensibility & Production Deployment Recommendations

  • Adding New AWS Tools: Implement a new tool in app/tools/, add its JSON schema to TOOL_DEFINITIONS in app/ai/tool_router.py, and expose a route in app/routes/aws.py.
  • Persistent Database: Swap the in-memory session store with PostgreSQL or DynamoDB for multi-user enterprise deployments.
  • Containerization: CloudSage can be packaged as a lightweight Docker container (Python 3.11-slim) and deployed as an internal ECS service or Kubernetes pod.
